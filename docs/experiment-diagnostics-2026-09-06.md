64,347 是 requires_grad 张量的元素数，包括分类器被冻结的行。按本次共享 91 类分类头、20 个新类计算，实际可改变的元素为 LoRA 40,960 + 新类分类头 5,140 = 46,100。日志计数不是 64,347 个元素都在有效更新。

当前 backbone、encoder、attention、query embedding、box head、旧分类器行被冻结。末两层 FFN LoRA 能通过共享特征间接影响分类与框，但没有直接训练上述模块。需要把“适配范围过窄”与“低秩 rank 太小”区分开。

回放数据还有两个细节：

1. cosine 的 36,510 张当前图与 256 张回放合并后只有 36,570 张，意味着按历史合并逻辑有 196 张回放与当前图重合。新流程为 36,510 + 398 = 36,908。旧回放可能同时补充已有图像的标签，不能只按新增图片数解释其作用。
2. 当前采样器记录每卡每轮 1,845 次回放，共约 3,690 次，即每张回放图片平均约 9.27 次。当前图曝光约 33,218 次，约为 36,510 张的 91%。因此“回放图片更多”与“每轮新类学习机会相同”不同时成立。尾 batch 和类别共现会造成细小偏差。

旧合并代码直接追加两份标注，当前实现增加了按源标注身份去重。包内没有原始 annotations/train_graph.json，不能确认旧文件实际有多少重复框，也不能声称已经发现标签泄漏。未来对照需要固定训练标注并记录哈希。

## 4. 三模块训练曲线

轮数以下从 1 开始，原始 metrics 的 epoch 从 0 开始。

| 轮数 | 学习率 | 总训练损失 | Previous AP50 (%) | Current AP50 (%) | Known AP50 (%) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 5 | 1e-4 | 11.2362 | 50.2264 | 12.1710 | 31.1987 |
| 10 | 1e-4 | 11.1153 | 50.4784 | 13.6448 | 32.0616 |
| 15 | 1e-4 | 11.0672 | 50.2699 | 14.2826 | 32.2762 |
| 20 | 1e-5 | 11.0177 | 50.4009 | 14.3174 | 32.3591 |

第 15 到第 20 轮新类 AP 只增加 0.0348 个百分点。按原学习率直接续跑较低优先级；但不能推论任何增加训练轮数都无效，需要先改变已定位的瓶颈。

最后 local margin 加权值 0.3403，off projection 加权值 8.93e-6。标量大小不等于梯度影响，因此不把投影约束过强当成已确认原因，也不直接把其系数放大若干数量级。

日志 grad_norm 约 10.7，裁剪阈值 0.1，返回值是裁剪前范数。存在强裁剪的迹象，但 epoch 均值无法恢复逐步裁剪比例；AdamW 的自适应缩放也意味着不能把 0.1/10.7 直接解释为学习率缩小 107 倍。暂不把改裁剪阈值放到首轮。

训练总损失包括六层辅助检测损失，前四层特征基本冻结，且共享分类器仍在更新；总损失平台不能独立证明过拟合或容量不足。验证损失是在 full-label 标注上算的，含尚未知类别，不能直接与训练损失比较来判定过拟合。

Stage 0 摘录的 AP50 约 50.2%，三模块旧类约 50.4%，cosine 旧类约 50.8%。表面上两者都接近起点；严格遗忘量需要在同一验证文件、同一旧类别集合上重新评估 Stage 0 权重后计算。

## 5. GNN：有排序信号，但不足以解释或解决全部差距

- 20 类，380 条有效有向边，138 条正边；每类特征最多 12 张图，校准 probe 为 3 步，batch size 为 1。
- 留出 4 个源类别，平均 Pearson 0.3343，Top-5 overlap 0.50。随机从 19 个候选选 5 个的期望 overlap 为 5/19，约 0.263，所以当前结果不是没有信号；但四个源类别的证据较弱。
- 训练损失 0.0012 是拟合指标。production_ready 表示源类别校准覆盖完成，不是预测质量达标。
- Stage 1 的 20 个新类中，13 个把旧类 87 排第一。它可能确实普遍脆弱，也可能是目标类别偏置。需比较实测干扰，不能据此直接判定 GNN 塌缩。
- 两种方法选中集合交集为 82、2、25，共 3/5。选邻居差异本身不能解释新类 AP 下降 41.10 个百分点。

GNN 后续优化顺序：

1. 先建立统一参数更新方式、回放预算、曝光、聚合规则的 GNN / cosine / random 对照。当前 runner 的 control 只有 graph/random/global，没有可直接运行的 cosine 参数；恢复 cosine 对照需只补评分选项，不能回退整套历史训练流程。
2. 类别梯度目前删除同图其他类标注后计算完整检测损失，可能制造假背景冲突。比较完整标注匹配后按类归属计算的梯度；probe 与 harm 评估应使用一致的类别损失定义。
3. 比较多个固定随机子集；把特征样本从 12 增到 32，并测试 probe 3 与 10 步。batch=1 时，仅增加 probe_max_images 而仍只更新 3 步，并不能让实际 probe 训练覆盖全部 32 张图。
4. 现有梯度压缩用平均池化，比较保留几何关系的固定随机投影；记录梯度范数和压缩前后内积保持情况。先测质量再加网络容量。
5. 校准的正损失增量按源行最大值归一化，跨源聚合不代表绝对干扰量可比。保留原始/相对 harm，比较排序和尺度特征，并报告多个留出划分与目标平均风险基线。

## 6. 建议的最小诊断实验

本轮只需先启动 D1、D2 两组。它们都保留三模块 v1 的起点、当前训练数据、GNN 邻域、回放配额/采样、教师补标、学习率 1e-4、seed 42。训练计划保持 20 轮、lr-drop 15、每 5 轮评估，先看第 5/10 轮。

| 实验 | LoRA | Local margin | Off projection | 相对现有 runner 命令的变化 |
| --- | --- | ---: | ---: | --- |
| D0，已有 | rank 8，末两层 | 0.5 | 0.1 | 无 |
| D1 | rank 8，末两层 | 0 | 0 | --local-margin-coef 0 --off-projection-coef 0 |
| D2 | 常规微调 | 0 | 0 | --no-neighbor-scoped-lora --local-margin-coef 0 --off-projection-coef 0 |
| D3，条件运行 | rank 16，末两层 | 0 | 0 | 在 D1 上仅改 --lora-rank 16 |

每次从 Stage 0 权重初始化，写入不同新目录，不能用 D0 训练后的权重启动消融。不要把 D2 的 off projection 保持为正，runner 会拒绝；该损失依赖 LoRA 坐标。

D1 与 D0 测试两个附加损失的组合影响，不是严格拆分两个损失；D2 与 D1 测试参数更新范围，包括旧分类器行/box head 等是否冻结，不是只比较矩阵秩。为了数据一致，应验证两个新实验的训练标注内容或 SHA-256 相同；该 runner 在固定种子下应重建一致回放，但仍要验证。

决策规则：

- D1 新类 AP 明显恢复：随后分别加回 margin 和 projection，再扫描 margin 0.1/0.5，查看各项对 LoRA 的梯度范数、方向及旧类代价。
- D1 仍接近原平台，D2 明显恢复：优先优化 LoRA 的适配范围。先 D3，再比较 last-decoder-layers 2 与 4（需要重建对应梯度/保护基）；之后考虑对 attention 投影或 box head 开放适配，但应作为单独实现变更。
- D1 和 D2 都弱：先核对训练标注/标签分布、教师伪标签质量、新类分类器初始化与加载，再比较 lr 1e-4 / 2e-4，不能继续只扩大 GNN。
- D1 的 LoRA 梯度很小而分类头梯度占优：检查共享分类器及六层辅助损失的贡献，再考虑分类头独立学习率或辅助损失权重。该建议需要新增诊断，不从当前总梯度直接推出。

当前 D0 的第 5/10 轮新类 AP 是 12.17/13.64，旧类 AP 是 50.23/50.48。新实验必须与同轮数比较；例如新类提高数个百分点并且旧类下降不到约 1 个百分点，可作为继续训练的工程筛选信号。这不是显著性阈值，最终结论需完整训练及多个种子。

确认适配方案后，再在相同方案下比较 GNN / cosine / random。统一 20 个旧类基础配额、额外总预算、去重后的实际图像数、每轮回放曝光和总更新步数，并使用相同风险聚合。不要把旧 cosine 历史结果填进新表作为严格同条件基线。

## 7. 未知类指标的独立问题

当前未知得分为 1 - max(sigmoid(logits))，低已知置信度的背景同样可能得高分。后处理先从 query×class 中取 top 100，同一个 query 可以因多个类别重复出现；未知统计没有先按 query 去重。

当前 compute_owod_metrics 的 UDP 为“被覆盖的未知 GT 数 / 未知预测条目数”，没有标准一对一 TP 匹配；A-OSE 的 known 候选只按类别 ID 判断，没有排除同时标为 unknown 的预测，且没有使用 pred_scores 做置信度过滤；WI 也采用本地简化计算。它们可作同实现的诊断值，但不能直接当作论文标准指标。此前把 UDP 简称为未知预测精度不够严格，应以这里的实现定义为准。

约 48.4 万个未知预测说明该输出/统计流程需要审计，不能仅凭其数量推断 48.4 万个独立错误目标。先统一匹配、候选去重和类别集合，再研究 foreground/objectness 与未知评分；仅提高 unknown_threshold 不会修复新类 AP50 14.32% 的问题。
